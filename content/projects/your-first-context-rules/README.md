There are two ways to write your context rules:

1. Before starting to build
2. In the middle of your building process

If you are starting to vibe-code my recomendation will be to stick to option number 2 because having some caode already written makes dramatically easier the process of coming up with new rules.

For example:

- If you are building an API in python you will probably have a `routes.py` and you can ask the AI to write a rule to describe how the file is written, the AI will take care of analyzing the file and describing it as a rule so tomorrow when new code is writen on that file, it follows the same standards.
